# Window behavior

Dev.6 does not change the established Normal, Maximized, and BorderlessFullscreen state model. Multi-document activation changes only the stacked document view and title metadata. Window resize, maximize, restore, and F11 do not reopen files or recreate retained sessions.

Discrete mouse-wheel input uses one reusable floating-point, elapsed-time controller. Repeated input extends the live target without resetting velocity; direction changes alter that same trajectory. A critically damped analytic step uses real elapsed time and imposes no fixed pixels-per-frame cap, so rapid input can move far while retaining coherent velocity. Qt Widgets' raster backing store has no dependable presented-frame callback. A precise timer requests viewport updates at 16 ms normally and 8 ms only while distance/velocity is high; state advances in the resulting paint event. The faster request cadence prevents a timer/display phase miss from dropping a physical 60 Hz presentation while avoiding high-rate idle or slow-motion work.

Precision pixel/touchpad input, scrollbar dragging, keyboard paging/Home/End, outline activation, heading links, tab restoration, and layout-anchor correction are direct. Mouse or keyboard takeover cancels wheel motion. Sidebar width remains a native property animation but reverses from its actual partial width. `WOLFMARK_REDUCED_MOTION=1` makes Wolfmark-owned wheel and outline motion direct.

Middle-button autoscroll keeps its existing 16 ms motion timer and distance-based speed curve. While active, the document viewport paints a neutral Wolfmark anchor after the QTextEdit content at the exact viewport-local click origin. It is not a child of the scrolling viewport, so document movement cannot translate it. The anchor uses Wolfmark palette tokens at logical-pixel size, so Qt handles display scaling without copied browser artwork. Escape, a second middle click, a normal click, reload, or session replacement immediately stops the timer and removes the overlay; the former generic vertical-resize cursor is not used.

`--smoke-scroll-profile` enables a bounded in-memory frame trace and reports input-to-first-paint, paint-interval p50/p95/p99/worst, threshold counts over 16.67/25/33.3/50 ms, paint cost, scrollbar/value-change cost, and image scan/delivery cost. It emits one summary rather than logging each frame. `WOLFMARK_SCROLL_PROFILE_OUTPUT` optionally writes that summary to a file, which is useful for the Windows GUI-subsystem Release executable.

Wolfmark uses one frameless Qt Widgets window with an integrated charcoal title bar. The dedicated `WolfTitleBar` component retains Qt's `QWindow::startSystemMove()` path as the portable fallback. On Windows, `windows_window_frame.*` supplies the native non-client contract while Qt continues to own and paint the HWND. Document/core state remains independent.

On Windows 11, the native adapter requests rounded DWM corners for a restored window and explicitly requests square corners while maximized or in borderless fullscreen. Returning to Normal reapplies the rounded preference. Qt still owns the top-level window and client rendering; Wolfmark does not clip the QWidget into a simulated window shape. Older Windows versions may ignore the unsupported DWM attribute and keep their native behavior.

Rust tracks three semantic modes: `Normal`, `Maximized`, and `BorderlessFullscreen`.

Normal maximize uses the operating system's standard maximize/restore operation. Wolfmark chrome remains visible and the Windows work area keeps the taskbar visible. F11 is separate same-window borderless fullscreen: Wolfmark preserves the prior Normal/Maximized mode, hides its title bar (including document actions) and optional diagnostics row, fills the current screen through Qt, and restores the saved mode on F11 or Escape.

Qt's frameless HWND already carried the system-menu and minimize/maximize capability bits, but it lacked `WS_THICKFRAME` and reported only resize edges through `WM_NCHITTEST`. The Windows adapter adds the missing resize/snap eligibility bit without replacing the frameless Qt window or forcing a visible native caption. Forcing the full `WS_CAPTION` style onto this qwindows backing-store path was tested and rejected because it invalidated client painting.

The adapter reports live Qt widget geometry as `HTCAPTION`, `HTMAXBUTTON`, and the appropriate resize edge/corner values. Minimize and close deliberately remain `HTCLIENT` Qt controls so they keep their normal QAbstractButton input path. Maximize alone uses the native hit role required by Windows 11; its non-client press/release is bridged back to the same Qt button action and paint state. `DwmDefWindowProc` receives the relevant non-client hover/hit-test messages first. This avoids the dead half-native state where Windows owns an input region but no native or Qt action runs. Other interactive title-bar children remain excluded from the caption region.

On Windows 11 the custom maximize region returns the documented `HTMAXBUTTON` result required for the genuine system Snap Layout flyout. Wolfmark does not draw or simulate that flyout. The native smoke validates the style and hit-test contract; actual hover presentation remains a physical Windows acceptance check because it is DWM-owned.

Resize, zoom, maximize, F11, and restoration operate on the existing QTextDocument. The native smoke matrix asserts zero parse, file-load, document-construction, and image-request deltas across those transitions.

Physical Windows checks still required before release: top/left/right edge snapping and Snap Assist, maximized-window tear-off, the Windows 11 Snap Layout hover flyout, mixed-DPI multi-monitor movement, exact taskbar work-area behavior, title-bar drag/resize cursors, system-menu details, focus, and Normal-to-F11 geometry restoration on more than one monitor.

The current shell uses a 252px collapsible sidebar and 52px breadcrumb header. F11 hides the sidebar as well as the header; leaving it restores the user's sidebar preference subject to responsive width. The navigation smoke covers keyboard outline activation, automatic narrow-window collapse, and fullscreen chrome visibility without document reconstruction.
